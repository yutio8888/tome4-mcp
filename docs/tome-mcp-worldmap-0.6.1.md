# ToME MCP 0.6.1：世界地图可见地形修复

2026-09-15。正式 Bridge / Python server **0.6.1**，ToME **1.7.6**；协议 v1 / v2 保持兼容。

修复 [0.6.0 普通战役反馈](mcp-campaign-continuation-0.6.0.md)中的世界地图漏报。同一份已发布的 5 级世界地图存档，原来身周 625 格全部未知，现在正确报告 **39 个当前可见格**及两处入口，其余 **586 格保持未知**。

## 安装与实现

- [正式安装包](../dist/tome-mcp-bridge.teaa)；[冻结的本版副本](../validation/2026-09-15-worldmap/tome-mcp-bridge.teaa)。34 个生产文件，SHA-256：`7df97a9121ac75470436f48c136dbe366f12b083688f0c508d1c86e367e7af0e`。
- Python 服务位于 `tools/tome-mcp-server`；本地 `tmp/tome-mcp-venv` 的源码及安装元数据均为 0.6.1。更新 addon 后重启隔离游戏，显式使用 `tome.connect(mode="control", protocol_version=2)`。
- 世界地图的原生 `playerFOV` 在 `computeFOV → applyLite` 后直接返回，只填写当前可见缓存，不填写 `infovs`。原观测条件要求二者同时存在，导致地形全部被过滤。
- 现在只有世界地图且四个相关方法的身份及完整源码校验和均匹配时，才采用这条原生可见路径。没有改写或主动执行视野计算。普通地牢仍要求 `seens + infovs`，并保留地形下方角色的光照限制和失明保护。
- 不导入原生 `remembers`、历史发现地点或全图照明。`known` 只记录本桥接会话实际观察过的地形；`visible` 表示当前可见。视野外不读取地形变化或隐藏入口。地图窗口仍最多身周 12 格。

已有 `name`、`is_exit`、`block_status` 足以描述本次可见通路，无需暴露内部目的地数据。通行标记只描述地形；移动和进入仍交给原生命令判定。
